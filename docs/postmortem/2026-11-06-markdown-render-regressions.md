# Markdown 渲染回退成源码

## 现象

流式输出中的 LaTeX 公式会先渲染成 KaTeX，随后突然变回原始 `\frac{...}` / `$$...$$` 文本。
同类问题也影响普通 Markdown：长回复、hydration 更新或片段封存时整段内容短暂显示为源码。

## 原因

`MarkdownPiece` 用 `ready` 决定显示 `Streamdown` 还是 `PlainText`，而 `ready` 在文本变化时会失效：

- 活动尾部超过 4096 个字符时，`ready` 立即变为 false，整块已渲染内容替换成完整源码；如果没有
  空行边界，它会一直保持源码直到流结束。
- 稳定 segment 封存、消息结束、消息体 hydration 都会让 `formatted !== text`，在格式化队列
  跑完前先显示源码。
- 单独的 `$$` 围栏被归一化器当作普通行，关闭行后面再跟正文时 remark 认为数学块未闭合，
  KaTeX 把 `\frac{a}{b}\n$$ tail` 整段渲染成红色错误源码。

队列本身没有错：解析是异步的，错在等待期间把已经渲染过的 DOM 换成了源码。

## 现在的约束

- 片段一旦渲染过，就不再回退成源码。文本变化时保留上一份 `display`，队列提交新解析后再替换。
- 活动尾部 ≤4096 时每个 delta 直接进入增量 splitter；更大时按长度放慢快照推进
  （180–1600ms），既保留已渲染内容，又限制同一个未闭合块的重解析频率。
- 首次放行前从未渲染的片段（包括视口外的封存段）仍显示源码，超出 64K 的静态块仍显示源码和
  「格式化 Markdown」按钮；已渲染过的片段只保留渲染并显示按钮。
- `$$` 单独成行的数学块在归一化时跟踪开关状态；关闭行带正文时把正文拆到下一行，保证 remark
  能闭合数学块。

## 回归覆盖

- `web/e2e/markdown-stream.spec.ts`：长数学段落逐帧采样，首次渲染后 `.katex` 不能再归零，
  `data-md-tail` 不能再出现；长列表流式期间保持渲染。
- `web/e2e/markdown-math.spec.ts`：`$$` 关闭行后的正文不再产生 `.katex-error`。
- `web/unit/math-delimiters.test.ts`：关闭行带正文的归一化输出。
