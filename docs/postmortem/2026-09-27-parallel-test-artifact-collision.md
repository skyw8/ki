# 并行测试的产物目录也需要隔离

2026-09-27 的反馈延迟审计发现：Playwright 的临时 home、端口和鉴权状态已经按 invocation
隔离，但外围 runner 仍将二进制与报告写入固定 `test-results/e2e-parallel/`，且每次启动都会
递归删除它。两次测试并发时，后启动的一次可能删掉前一次仍在使用的二进制或 JSON 报告。
这是固定测试路径问题在产物层的重复；仅隔离服务状态还不完整。

runner 改用 `mkdtemp` 创建 `test-results/e2e-parallel/run-*/`，每轮拥有自己的二进制、
sidecar 和报告，启动时不删除其他运行的文件。CI 的失败日志搜集同步匹配新的目录层级。
用两个同时运行的 shots runner 验证：两轮均完整通过，产物保存在不同目录。

覆盖核对也从总数改为测试 ID：少测一条、多测另一条不会再因总数相同而通过；skipped 或
未开始执行的 spec 不计为已执行。Bun 回归验证了等数量替换、重复、未知和跳过用例的拒绝行为。

只读构建产物可以在一轮中复用，鉴权、可变数据、报告和清理范围必须有明确的 invocation
归属。提速前先检查每条共享路径的写入与删除者。
