# 抽屉与子菜单重复消费 Escape

完整回归的 320×568 手机用例偶发无法在关闭会话菜单后恢复触发按钮焦点。
失败快照中菜单与导航抽屉同时消失，触发按钮所在侧栏已变为 inert。

菜单自身的 React key handler 会阻止 Escape 冒泡，但它依赖焦点已经进入菜单。
菜单初始焦点在 requestAnimationFrame 中设置；此前 Escape 从抽屉按钮冒泡到
window，菜单与抽屉的两个监听器都会关闭各自的层。单独验证“菜单消失”无法
发现父层也已关闭，高负载让这个窗口更容易暴露。

修复让抽屉的键盘监听器在子菜单打开时让出 Escape，与焦点是否已进入菜单无关，
同时尊重 defaultPrevented。第一次 Escape 关闭菜单并恢复按钮焦点；第二次才
关闭抽屉。新增独立浏览器回归明确把焦点留在菜单外，再验证两次 Escape 的层级
与焦点恢复，保留原有响应式矩阵的 focus 断言。
